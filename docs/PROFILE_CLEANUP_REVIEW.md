## 复现与修复

负责人独立注入首个timeout夹具的 `ChildProcess.kill() => false`：旧版直接进程仍活着，原退出未确认标记被断言错误替代，配置及目录均已删除；新版同条件下原标记向外传播，配置及目录均保留。两次均在检查后恢复真实kill、确认自有进程exit，再清理。这里模拟终止请求失败，不是遇到实际OS拒绝终止；也不涉及真实默认玩家配置。

`rejectsAfterConfirmedExit` 在预期失败断言之前检查原始错误；三处真实运行器拒绝路径（基础循环、协作超时、无响应超时）均使用该入口，退出未确认直接原样throw。最外层catch保留标记，finally不删目录。人工构造的false例子没有真实写者，继续显式安全清理，不能混同实际进程场景。

新增 `tests/profile-cleanup-regression.mjs` 在当前Node中注入一个真实自有夹具，以独立ESM query执行完整 `test-profile.mjs`，避免完整套件此前import过同模块而跳过复验。检查原Error对象传播、活进程、目录和配置内容保留；恢复全局钩子后恢复真实kill，等待确认退出才删精确归属目录，没有外层Node硬杀超时。新增回归在修改前失败，不能只验证内层 `withOwnedProfile`。
