## 实现与运行方法

`scripts/test-profile.mjs` 先启动没有Session/autoload的临时探针项目，让Godot返回实际 `user://` 路径，避免按操作系统猜目录。父进程用独占创建保留随机 `test-owned-*` profile，再以 `--profile` 传给子进程；清理只删除该次保留的精确文件，不使用客户端回传路径作删除目标。默认配置与其他未知配置不属于本次运行。探针临时目录也有绝对路径边界检查。

`checkedGodot` 在实际子进程关闭后执行父进程清理；启动失败也有已登记的归属。原测试脚本中仅成功退出时的自删逻辑移到父进程，涵盖异常和超时。真实网络测试在启动客户端之前登记配置，并核对回报路径与登记路径完全一致；一个客户端清理失败不跳过另一个客户端。未经确认退出的进程不提前删其配置。

Windows上强杀Node不会可靠执行其 `finally`，所以测试外层超时先发送固定IPC停止通知。IPC在这里仅用于本机测试进程之间协调退出，不是新的游戏网络传输。network收到通知后退出等待、停止自有Godot、清理配置，然后启动器停止自有后端。停止通知处理提前于初始化等待；每次启动新资源前再次检查停止状态，防止清理后又启动。

网络协作停止预算40秒；自有Godot每次停止先等5秒，再尝试强制结束并再等5秒；后端启动器收尾预算45秒；完整测试的外层清理宽限100秒。超出宽限或IPC不可用会明确报告后代清理未验证，整轮失败。系统关机、杀掉最外层父进程或操作系统拒绝结束进程不在清理保证内；不能据此删除未知配置或宣称不存在残留。

自动导入、单元测试、独立导出和实际PCK审计都经过同一profile所有权包装。完整测试在同一个父进程调用profile检查与导出，避免在它们收尾前另一个超时先杀掉所有者。独立 `npm run test:network` 已显式启用协作停止；普通手动客户端启动方式保持不变。

设置本机 `GODOT`、`NAKAMA_BIN` 后：

```powershell
$env:SCARF_ANALYTICS = 'false'
$env:NAKAMA_TELEMETRY = '0'
$env:TEST_GUI = '0'
node scripts/test.mjs
```

无需后端的定向验证：

```powershell
node tests/test-profile.mjs
node scripts/test-godot-unit.mjs lobby_state snapshot_timeline sdk_socket_lifecycle
node tests/timeline-freeze-regression.mjs
node scripts/export.mjs
```

单测入口只接受列出的测试名，不接受任意路径。直接运行裸 `Godot --script` 仍会初始化Session并使用默认profile；需要隔离时使用上述入口。单独网络测试仍需先生成相应生产/fixture构建，沿用README与第一阶段运行说明。
