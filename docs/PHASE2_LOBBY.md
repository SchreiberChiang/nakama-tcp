## 范围与验收

本阶段只完善客户端大厅：刷新保留房间名、容量、所选玩法和键盘焦点；区分加载、成功空列表与失败；失败保留最后有效列表并提示可能过期；旧请求不能覆盖新请求、连接或房间状态。保留空生产注册、普通二维公共界面及第一阶段协议与输入/呈现能力。没有修改服务端、生产时间轴、玩法协议或传输路线。

验收先用实际 Session 和 Main UI 复现，再用可控 SDK 回调覆盖响应顺序、失败与同步信号重入，最后运行本地真实双客户端和原完整回归。只有测试替身控制回调完成时机；没有用手动发送成功信号代替被测刷新逻辑。

## 接口与边界

- `Session.rooms_state` 为 `idle/loading/ready/error`，`rooms_state_changed` 表示列表状态变化；`rooms_updated` 只通知当前请求成功得到有效列表。失败不会伪装成成功的空列表。
- `rooms_have_success` 表示当前连接/大厅上下文曾成功取过列表。成功为空仍是成功；错误时保留已有列表，界面明确提示过期与手动重试。加入行为最终仍由服务端裁定，旧列表不保证房间仍可加入。
- 刷新用“请求序号”识别最新请求，用“连接代际”和“房间代际”识别所属上下文。代际就是切换连接或房间时递增的编号：迟到的结果即使内容正确，也不能再作用于新上下文。请求前、回调后、同步状态通知后都检查所属上下文。
- 建房/加入开始会使此前刷新失效；加入中或房间内不发列表请求。建房期间由代码主动发起的新刷新仍属于当前大厅，允许只更新列表；自动加入开始会再次使未完成刷新失效。没有后台轮询或自动重试。
- 界面仅重绘列表区域，保留建房表单节点与焦点。显式重建大厅时按玩法 ID 恢复选择，不依赖列表下标；已移除的玩法回退到当前有效项。草稿保证限定于大厅刷新，不保证进入房间再离开后保存最新草稿，也不持久化到磁盘。
- 注销、新连接、断线、离房和服务端成员移除清空列表上下文。主动离房原有延后刷新行为保留；服务端成员移除返回大厅后显示尚未加载，可手动刷新。
- 检查列表中界面消费的字段及类型，拒绝不完整响应。解析错误不输出原始响应；界面只显示固定安全文案。定向测试与运行器用私密哨兵检查输出。现有通用 RPC 路径没有在本阶段整体重写。

上述字段与信号属于客户端接口，不改变线上消息格式，协议仍为 v2；不因此宣称兼容旧赛车云服。

## 运行方法

准备 Node 24、Godot 4.7.2 与 Nakama 3.41.0，按 README 设置 `GODOT` 与 `NAKAMA_BIN` 为本机路径：

```powershell
npm.cmd ci --ignore-scripts
node scripts/restore-source-assets.mjs
$env:SCARF_ANALYTICS = 'false'
$env:NAKAMA_TELEMETRY = '0'
$env:TEST_GUI = '0'
node scripts/test.mjs
```

大厅定向测试无需后端：

```powershell
$profile = 'unit-lobby-' + [guid]::NewGuid().ToString()
```
