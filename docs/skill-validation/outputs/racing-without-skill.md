**怎么做到跟手又防改客户端**

- 玩家按下转向，本机立即计算并显示车辆转向，同时向服务器发送油门、刹车、方向等操作。
- 服务器独立计算位置、速度、斜坡接触、腾空、碰撞和圈数。客户端上报“我已到终点”不能直接生效。
- 服务器回传车辆状态及已处理的输入编号。本机用这个状态重算尚未确认的操作，小误差平滑修正，大误差及时归位。
- 别人的车按收到的状态平滑移动。车车碰撞由服务器统一裁决；本地可以先表现碰撞反馈，但不能决定最终推力和结果。

保留 `seq/round_id/sessionId`、连接与房间代际检查、数据格式、容量和限流校验，客户端仍通过 Session 调用 SDK。服务器还应限制操作范围、处理时序和每步位移，避免“多发包就跑得更快”。这能压住改速度、瞬移、伪造成绩等作弊，不能承诺消灭所有作弊。

**斜坡、腾空和碰撞是最需要先验证的部分。** 建议先采用简化的街机车辆模型，让客户端和服务器使用可对齐的运动规则。服务器必须能表达赛道高度、落地和碰撞，不能仅转发坐标。若底座缺少这些能力，这是新增工作，不能只靠提高发包频率解决。也不要预设微信和电脑的物理引擎会算出完全相同的结果。
