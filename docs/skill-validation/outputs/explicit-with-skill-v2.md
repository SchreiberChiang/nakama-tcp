建议交互拆分如下：

| 类别 | 首版处理 |
|---|---|
| 持续状态 | 移动、瞄准由服务端计算，双方可见；新输入覆盖旧输入，失效清零，显示容忍短暂陈旧 |
| 一次命令 | 跳跃、单次开火由服务端裁定；本机立即反馈尝试，伤害等权威结果到达后显示 |
| 按需获取 | 大厅目录、房间列表沿用现有请求；失败显示重试，旧响应不得推进页面 |
| 本机表现 | 镜头、音效、枪口闪光本机即时播放，不上传为命中证据 |

持续输入目标30Hz、模拟30Hz、默认整房快照20Hz，渲染帧率另算；首步保留这些值再测手感。`submit_input` 不返回序号，逐枪反馈可用模块 `action_id` 返回业务结果；接受、消费、命中不能混同，回执窗口外保留 unknown，不自动重发。

第一步建议先确定“一屏、一种武器、一种目标、移动/跳跃/开火→结算→再来一局”的验收合同；获开发授权后才做独立测试模块。断线、后台或成员移除暂定结束本局；后台沿用注销后手动重登，不能恢复原局；晚加入继续拒绝，房主离开仍由服务器移交控制角色。重复动作需验证不重复伤害。

验收应覆盖微信与电脑同房、松手停止、同时移动开火、权威伤害一致及完整生命周期，再做适用构建、SDK测试、双端测试和实际PCK审计。失败退回空注册底座；共享容量或平台接入改动单独回退，评估两端兼容及未知外部使用方。
