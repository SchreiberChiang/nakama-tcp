建议首版按**双人1对1、单屏2D小地图、左右移动＋自由瞄准＋低射速可见弹丸**设计，暂不加跳跃、复杂地形和多武器。电脑用键鼠，微信用左侧移动、右侧瞄准开火；可见弹丸方便理解躲避，也能先验证跨端手感。对战模式是暂定假设。

本次仅静态读取，当前 HEAD 为 `a5422e7`；未修改、联网或运行。推荐依据如下：

- **底座已有**：Session统一发送输入，服务端校验身份、轮次、序号；模拟30Hz、持续输入约30Hz、默认整房快照20Hz，支持结算和下一局。两端生产注册表仍为空。见 [Session](/<with-skill>/client/core/session.gd:93) 与 [服务端](/<with-skill>/server/src/main.ts:974)。
- **模块适配**：新增移动、碰撞、弹丸、血量和胜负规则，由服务端计算；客户端只提交操作。规则放服务端模块，公开状态经投影给双方，视图仅在对局中创建，共享页面保持2D。
- **底座新增**：当前容量默认8，`minimumPlayers=2`不能强制最多两人；严格双人需增加服务端玩法容量上限。影响共享建房合同，两端需协调升级，外部使用方兼容性未核实。

公平与跟手分别处理：

| 交互 | 首版处理 |
|---|---|
| 移动、瞄准：持续状态 | 本机立即反馈，双方接收权威位置；旧输入被新状态覆盖，超时清零。对手插值允许短暂陈旧。 |
| 开火：一次命令 | 携带当次瞄准及业务动作ID；服务端检查射速并生成弹丸。同tick统一判碰撞、结算伤害，避免按成员顺序先判死。 |
| 枪口、准星、音效：本机表现 | 下一帧响应；命中提示和扣血等待权威结果，不能先宣告打中。 |
| 房间列表：按需 | 刷新后展示；失败保留错误提示，加入资格仍由服务端确认。 |

开火结果用模块动作ID关联并投影；重复动作在本轮有界去重，不盲目重发。**提交、接受、消费、实际出弹/命中不是同一件事**；回执窗口外保留“未知”。现有 `submit_input()` 不返回序号，无须为业务反馈直接改SDK边界。

手感建议目标60fps，但它不等于网络60Hz。本机简单移动预测＋权威纠正可在模块实现，属于新工作；对手复用时间轴。现有[时间轴](/<with-skill>/client/core/snapshot_timeline.gd:2)没有预测重演或命中回溯。先保留30/30/20Hz测量；提高快照率不能消除延迟差异。若要高速即时命中，再评估受限回溯、时间校验及“躲进掩体仍受伤”的取舍。

首版建议后台清输入并退出，断线/移除结束本局，不恢复原局、不允许晚加入；房主离开照常移交，权威仍在服务器。后台策略目前只装在测试入口，需正式接入；结算、留房再来沿用底座。
