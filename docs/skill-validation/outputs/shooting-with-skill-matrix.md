**模块适配：第一版怎么做**

1. **持续状态**：移动方向、瞄准方向走 `state`，只保留最新值；服务器计算位置。自己角色本地立即移动，再按权威位置纠正；对手用插值显示。这种简化预测需新写，先测纠正距离和频率。
2. **开火事件**：每发走 `command`，携带当次瞄准方向，避免被之后的瞄准覆盖。服务器检查射速、存活状态，从权威枪口生成子弹，用扫掠碰撞防穿透，统一计算伤害和胜负。同tick伤害统一结算，避免成员遍历顺序决定赢家。
3. **反馈与结果**：准星、枪口火光、声音下一帧本地响应；扣血、命中标记和击杀等服务器确认。双方看到权威子弹、血量；短暂事件需模块提供有界事件编号和去重，不能只存在一个模拟tick。命令不自动重发，回执缺失保留“未知”；`applied`只表示消费，不等于命中。
4. **按需与表现**：地图、武器参数随模块加载，镜头和粒子留本机。渲染先以60fps为目标，模拟30Hz、输入30Hz、快照20Hz保持基线；均需真机测量，不承诺达标。

**底座新增及取舍**

`submit_input()`目前返回 `void`；若要精确关联预测开火与回执，最小扩展是公开提交标识。完整预测重演需要额外输入历史与确认语义，不能把最高消费序号当连续确认。瞬时枪若要求“瞄准所见即命中”，还需历史碰撞体、可信时间映射和受限回溯；现有 `client_tick`不是开枪时刻。首版飞行弹先不引入这套成本。
