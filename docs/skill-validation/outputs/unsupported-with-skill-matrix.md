1. **每辆车不同发送频率：部分模块适配，部分底座新增。**  
   **底座已有**：模拟固定30Hz，持续输入默认30Hz；快照默认20Hz、可配置10/30Hz，但统一调度整房、逐接收者发送，并非逐车调频。见 [Session._process](<<with-skill>/client/core/session.gd:93>)、[快照调度](<<with-skill>/server/src/main.ts:1012>)。  
   若指各玩家上传控制，模块可自行定时调用 `Session.submit_input`，关闭默认持续发送，保留完整state与心跳，避免默认0.5秒超时清零。若指车辆状态下发，少更新字段仍会重复传输；真正节流需要对象时间戳、增量合并与补全机制，建议扩展底座。渲染帧率独立，尾气、镜头留本机。

2. **断网30秒回原局：底座新增。**  
   当前[加入门禁与离开处理](<<with-skill>/server/src/main.ts:396>)拒绝非大厅加入、移除离线成员；空房约10秒回收，客户端断开后清房间身份。  
   推荐限定“服务端未重启”：保留席位和车辆至少30秒，重新认证后绑定新presence，拒绝旧连接输入，补发全量状态。模块决定车辆停车还是托管；底座处理全员掉线、房主移交、踢出不恢复、超时释放，以及已结算或换轮后的去向。跨服务端重启恢复另需持久化。

3. **购买自动重试且只扣一次：底座新增。**  
   [command_results](<<with-skill>/server/src/main.ts:62>)仅有32条内存结果；`applied`表示消费，不保证扣款发货成功，异常也不回滚。`submit_input`返回void，不公开提交序号。  
   推荐独立购买接口，经Session调用：稳定订单ID绑定账号、商品和价格版本，持久去重，将扣款、发货、订单结果纳入可验证的原子事务；重试复用订单ID，退避并查询结果。无结果显示“待确认”，不能用最高seq推断成功。保障目标是成功订单只扣一次；断网期间不能保证立即完成。

4. **射击命中回溯：主要模块适配。**  
   [模块合同](<<with-skill>/server/src/types.ts:1>)提供input/step，可维护有界权威碰撞历史，但没有现成回溯。当前时间轴只是客户端二维插值；`client_tick`是最近收到的快照tick，并非开火时刻。  
   推荐模块新增开火命令、受约束的呈现时间、射速/弹药校验及历史碰撞查询，由服务端判伤；枪口反馈本地即时播放。回溯上限先取待测假设，明确掩体后受击取舍；若需通用时钟测量，再扩展底座。
